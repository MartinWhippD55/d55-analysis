# Requirements Document

## Introduction

This document specifies the requirements for Estimate 4 of the Bryt Energy Contract Note Rework project. The system enables business users to create and manage bespoke (custom) contract notes for customers that require non-standard terms, pricing presentations, or VIP treatment — cases where the automated template-matching pipeline from Estimate 1 is not appropriate.

Bespoke contracts are identified by a flag on the customer's Salesforce record. When the automated pipeline encounters a flagged customer, it skips processing entirely. Business users then manually create, edit, and render bespoke contract notes through a dedicated section of the Admin Portal, using the same section-based editor from Estimate 1 but applied to one-off documents rather than reusable templates.

## Glossary

- **Bespoke_Contract_Note**: A one-off contract note created manually for a specific customer, not generated by the automated pipeline
- **Bespoke_Flag**: A field on the Salesforce customer record indicating the customer requires a bespoke contract note (e.g., `requires_bespoke_contract = true`)
- **BrytNumber**: The unique customer identifier (`customerreference` in the contract payload) used to identify and correlate bespoke contracts
- **Bespoke_List**: The table in the Admin Portal showing all bespoke contract notes with their status
- **Bespoke_Editor**: The editing interface for composing a bespoke contract note, reusing the section-based approach from Estimate 1
- **Clone_From_Template**: The action of creating a new bespoke contract note by copying an existing template's section structure as a starting point
- **Render_Status**: The lifecycle state of a bespoke contract note (draft, rendering, rendered, failed)
- **Bespoke_Version**: A saved state of a bespoke contract note's configuration, enabling version history and re-rendering

## Requirements

### Requirement 1: Pipeline Skip for Bespoke Customers

**User Story:** As a system operator, I want the automated pipeline to skip customers flagged for bespoke contracts, so that no automated render or DocuSign flow is triggered for them.

#### Acceptance Criteria

1. WHEN the Render_Pipeline receives contract data for a customer whose Salesforce record has the Bespoke_Flag set, IT SHALL skip rendering entirely and log that the customer requires a bespoke contract
2. THE Render_Pipeline SHALL NOT write any output PDF for bespoke-flagged customers
3. THE Render_Pipeline SHALL NOT trigger the DocuSign flow (Estimate 2) for bespoke-flagged customers
4. THE Render_Pipeline SHALL write a record to DynamoDB indicating that a bespoke contract is pending for this customer (BrytNumber, offer reference, timestamp, contract data S3 key)

### Requirement 2: Bespoke Contract Note Listing

**User Story:** As a Business_User, I want to see all bespoke contract notes in a list, so that I can track which ones are pending, in progress, or completed.

#### Acceptance Criteria

1. THE Admin_Portal SHALL display a Bespoke_List showing all bespoke contract notes
2. THE Bespoke_List SHALL display: customer name, BrytNumber, offer reference, status (pending, draft, rendered), created date, last modified date, and the user working on it
3. THE Bespoke_List SHALL be filterable by status
4. WHEN a bespoke contract note has been rendered, THE Bespoke_List SHALL display a link to download the rendered PDF

### Requirement 3: Bespoke Contract Note Creation

**User Story:** As a Business_User, I want to create a bespoke contract note for a customer, so that I can begin composing their custom document.

#### Acceptance Criteria

1. WHEN a Business_User creates a new bespoke contract note, THE Admin_Portal SHALL allow them to select from pending bespoke requests (customers who arrived via the pipeline skip)
2. THE Admin_Portal SHALL allow the Business_User to choose a starting point: clone from an existing template or start from scratch (empty)
3. WHEN cloning from a template, THE Admin_Portal SHALL copy all sections from the selected template into the bespoke contract note as independent copies (not references to the template)
4. THE Admin_Portal SHALL set the initial status to "draft" and record the creating user

### Requirement 4: Bespoke Contract Note Editing

**User Story:** As a Business_User, I want to edit a bespoke contract note using the same section-based editor as templates, so that I can compose custom layouts without developer assistance.

#### Acceptance Criteria

1. THE Bespoke_Editor SHALL reuse the same section management interface as the Template Edit screen (add, remove, reorder sections)
2. THE Bespoke_Editor SHALL allow the Business_User to edit sections using the Section_Editor (pdf-me designer)
3. THE Bespoke_Editor SHALL allow the Business_User to add shared sections (headers, footers, T&Cs) from the existing shared section library
4. THE Bespoke_Editor SHALL display the contract data for this customer (from the original contract XML/JSON) as a reference panel, so the user can see what data is available for fields
5. THE Bespoke_Editor SHALL support version history for sections, consistent with the standard template editor (Requirement 16 from Estimate 1)

### Requirement 5: Bespoke Contract Note Rendering

**User Story:** As a Business_User, I want to render a bespoke contract note on demand, so that I can generate the PDF and review it.

#### Acceptance Criteria

1. WHEN a Business_User clicks "Save & Render" on a bespoke contract note, THE Admin_Portal SHALL invoke the render pipeline with the bespoke section configuration and the customer's contract data
2. THE render SHALL produce a PDF using the same section-render-and-stitch approach as the automated pipeline
3. WHEN rendering completes successfully, THE Admin_Portal SHALL update the status to "rendered" and provide a download link to the PDF
4. IF rendering fails, THE Admin_Portal SHALL update the status to "failed" and display the error message
5. THE Business_User SHALL be able to re-render after making edits (creating a new rendered version)

### Requirement 6: Bespoke Contract Note Version History

**User Story:** As a Business_User, I want to see the history of renders for a bespoke contract note, so that I can access previous versions of the document.

#### Acceptance Criteria

1. THE Admin_Portal SHALL maintain a render history for each bespoke contract note, showing: version number, render timestamp, user who triggered the render, and link to the PDF
2. THE Business_User SHALL be able to download any previously rendered version
3. THE Admin_Portal SHALL clearly indicate which version is the latest/current render

### Requirement 7: Manual DocuSign Trigger

**User Story:** As a Business_User, I want to send a rendered bespoke contract note to DocuSign for signing, so that the customer can e-sign the custom document.

#### Acceptance Criteria

1. WHEN a bespoke contract note has status "rendered", THE Admin_Portal SHALL display a "Send via DocuSign" button
2. WHEN a Business_User clicks "Send via DocuSign", THE Admin_Portal SHALL invoke the same DocuSign envelope creation logic from Estimate 2 (Salesforce lookup for contact details, envelope creation, webhook setup)
3. THE Admin_Portal SHALL display the DocuSign envelope status alongside the bespoke contract note (sent, completed, declined, expired)
4. WHEN the envelope is completed (signed), THE signed PDF SHALL be stored in S3 and attached to Salesforce following the same flow as Estimate 2

### Requirement 8: Contract Data Reference Panel

**User Story:** As a Business_User, I want to see the customer's contract data while editing a bespoke contract note, so that I know which fields are available for the template.

#### Acceptance Criteria

1. THE Bespoke_Editor SHALL display a collapsible reference panel showing the customer's contract data (parsed from the original XML/JSON)
2. THE reference panel SHALL group fields by category (offer details, customer details, pricing, MPANs, sites)
3. THE reference panel SHALL be searchable/filterable so the user can quickly find specific fields
4. THE reference panel SHALL show both the field name (as used in templates) and the current value for this customer

### Requirement 9: Authentication and Authorisation

**User Story:** As a Business_User, I want bespoke contract management to be restricted to authorised users, so that only appropriate staff can create and edit custom contracts.

#### Acceptance Criteria

1. THE Admin_Portal SHALL restrict access to bespoke contract management screens to authenticated users with the appropriate Cognito group membership
2. THE Bespoke_List SHALL show which user is working on each bespoke contract note
3. THE Admin_Portal SHALL allow any authorised user to edit any bespoke contract note (no per-user locking in this phase)
