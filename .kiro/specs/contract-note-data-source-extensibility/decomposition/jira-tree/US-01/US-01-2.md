- **What:** Modify Project Role trust policy to allow the data-source + enrich Lambda execution roles to assume it; expose PROJECT_ROLE_ARN as a CDK param/env var
- **Why:** This is the IAM trust seam. The data source API list/columns handlers (US-03) and the `enrich-data-sources` handler (US-05) can only inherit the Project_Role's Lake Formation grants if the Project Role trusts their execution roles. Exposing `PROJECT_ROLE_ARN` lets those downstream constructs pass it to their Glue/Athena-backed Lambdas.
- **Done when:**
  - The Project Role trust policy adds the `list-available-data-sources-role`, `get-data-source-columns-role`, and `enrich-data-sources-role` execution roles as trusted `AWS` principals alongside the existing `sagemaker.amazonaws.com` service principal.
  - Those Lambda roles have `sts:AssumeRole` for the Project Role ARN.
  - `PROJECT_ROLE_ARN` is exposed as a CDK parameter / env var for downstream constructs.
  - CDK synth renders the expected principals; a listed role can assume the Project Role and an unlisted role cannot (Property 12).

### Suggested approach

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "Service": "sagemaker.amazonaws.com" },
      "Action": "sts:AssumeRole"
    },
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": [
          "arn:aws:iam::{account}:role/{prefix}list-available-data-sources-role",
          "arn:aws:iam::{account}:role/{prefix}get-data-source-columns-role",
          "arn:aws:iam::{account}:role/{prefix}enrich-data-sources-role"
        ]
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
```
