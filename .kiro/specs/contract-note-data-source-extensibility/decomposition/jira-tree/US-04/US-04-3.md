- **What:** Property tests for dependency tracking (Property 5: dependency = union across variants)
- **Why:** Locks in Property 5 (dependency = union across variants), the correctness invariant behind the whole scanner. Random multi-page, multi-variant schemas exercise cases fixed examples miss.
- **Done when:**
  - A generator produces random multi-page schemas mixing namespaced (`{table}.{column}`) and core (non-`.`) element names across several variants.
  - The property asserts the recomputed dependency set equals the union of distinct table prefixes referenced across all variants.
  - Core names never produce a dependency and repeated references de-duplicate.

### Suggested approach

```typescript
// shared-lib/dependency-scanner.property.test.ts
import fc from "fast-check";
import { scanSchemaForDataSources } from "./scan-schema";

// A pdf-me element name: either a namespaced data-source field or a core field.
const tableName = fc.constantFrom("credit_data", "billing", "meter_reads");
const namespacedName = fc.record({ t: tableName, c: fc.string({ minLength: 1 }) })
  .map(({ t, c }) => ({ name: `${t}.${c.replace(/\./g, "_")}` }));
const coreName = fc.string({ minLength: 1 }).map((n) => ({ name: n.replace(/\./g, "_") }));
const element = fc.oneof(namespacedName, coreName);
const schemaDoc = fc.record({ schemas: fc.array(fc.array(element)) }); // pages -> elements

test("Property 5: dependencies = union of table prefixes across variants", () => {
  fc.assert(
    fc.property(fc.array(schemaDoc, { minLength: 1 }), (variants) => {
      const expected = new Set<string>();
      for (const v of variants)
        for (const page of v.schemas)
          for (const el of page)
            if (el.name.includes(".")) expected.add(el.name.split(".")[0]);

      const actual = new Set<string>();
      for (const v of variants)
        for (const t of scanSchemaForDataSources(v)) actual.add(t);

      expect([...actual].sort()).toEqual([...expected].sort());
    }),
  );
});
```
