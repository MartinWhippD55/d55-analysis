- **What:** Finalise CDK deployment: confirm API Gateway routes, Lambda->Project Role assume, Athena workgroup/results bucket, and env vars are all wired in the stack
- **Why:** This is the seam that binds every earlier wave's component into one deployable stack. Without it the `DataSourceApi` construct, the `enrich-data-sources` state, and the frontend panels exist but are not reachable or authorised at runtime. Finalising it is what makes the feature live and unblocks end-to-end validation (US-08-2).
- **Done when:**
  - The `DataSourceApi` construct is instantiated in `contract-note-stack.ts` and its `LambdaIntegration`s are wired to the `contract-note-data-sources`, template-scoped `data-sources`, and shared-section `data-source-dependencies` routes declared in `contract-note-foundation.ts::createRoutes`.
  - The `enrich-data-sources` state is inserted between `select-template` and `render-sections` in `render-pipeline.ts` and is registered in the `handle-failure` catch array.
  - The Project Role trust policy trusts the `list-available`, `get-columns`, and `enrich-data-sources` Lambda execution roles, and those roles hold `sts:AssumeRole` on the Project Role ARN (alongside the existing `sagemaker.amazonaws.com` principal).
  - The Athena workgroup and results bucket exist and the Project Role can use them.
  - `PROJECT_ROLE_ARN` and Athena config are passed as environment variables to the Glue/Athena-backed handlers and the `enrich-data-sources` state.
  - `cdk synth` / build passes and confirms all of the above are present and wired.

### Suggested approach

```typescript
// contract-note-stack.ts — CDK wiring checklist (confirm each is present & bound)

// 1. DataSourceApi construct + its LambdaIntegrations bound to createRoutes
const dataSourceApi = new DataSourceApi(this, 'DataSourceApi', {
  projectRoleArn: props.projectRoleArn,          // env: PROJECT_ROLE_ARN
  athenaWorkgroup: props.athenaWorkgroup,
  athenaResultsBucket: props.athenaResultsBucket,
});
// contract-note-foundation.ts::createRoutes must wire:
//   - contract-note-data-sources            -> list-available handler
//   - <template>/data-sources               -> attach/detach + get-columns
//   - <shared-section>/data-source-dependencies

// 2. enrich-data-sources state in render-pipeline.ts
//    chain: parse-input -> select-template -> enrich-data-sources -> render-sections -> stitch -> write-output
const renderPipeline = selectTemplate
  .next(enrichDataSources)     // NEW state, must sit here
  .next(renderSections)
  .next(stitch)
  .next(writeOutput);
// enrich-data-sources must also be in the handle-failure catch array:
enrichDataSources.addCatch(handleFailure, { resultPath: '$.error' });

// 3. Project Role trust policy — add the three execution roles as AssumeRole principals
projectRole.assumeRolePolicy?.addStatements(new PolicyStatement({
  actions: ['sts:AssumeRole'],
  principals: [
    listAvailableFn.role!.grantPrincipal,
    getColumnsFn.role!.grantPrincipal,
    enrichDataSourcesFn.role!.grantPrincipal,
  ],
}));
// and grant each function sts:AssumeRole on the Project Role ARN:
projectRole.grant(listAvailableFn.role!, 'sts:AssumeRole');
projectRole.grant(getColumnsFn.role!, 'sts:AssumeRole');
projectRole.grant(enrichDataSourcesFn.role!, 'sts:AssumeRole');

// 4. Athena workgroup + results bucket, Project Role granted use
athenaResultsBucket.grantReadWrite(projectRole);

// 5. Env vars on every Glue/Athena-backed handler + the enrichment state
for (const fn of [listAvailableFn, getColumnsFn, enrichDataSourcesFn]) {
  fn.addEnvironment('PROJECT_ROLE_ARN', projectRole.roleArn);
  fn.addEnvironment('ATHENA_WORKGROUP', athenaWorkgroup.name);
  fn.addEnvironment('ATHENA_RESULTS_BUCKET', athenaResultsBucket.bucketName);
}
```
