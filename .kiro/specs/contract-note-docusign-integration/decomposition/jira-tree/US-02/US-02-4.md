- **What:** Property tests for the Salesforce client (Property 2: lookup correctness; Property 3: missing contact halts)
- **Why:** Locks in the two correctness properties for the lookup path so regressions in contact resolution or error handling are caught automatically. Optional — deferrable for a faster MVP.
- **Done when:**
  - **Property 2 (lookup correctness):** for any valid `customersalesforceref` resolving to a record with an email, `lookupContact` returns that email as the contact email.
  - **Property 3 (missing contact halts):** for any ref that doesn't exist or has no email, `lookupContact` throws and surfaces the `customersalesforceref`.
  - Tests use fast-check generators over random contacts with/without email and pass.

### Suggested approach

```typescript
import fc from 'fast-check';

// Property 2: Salesforce lookup correctness
test('returns the record email for any resolvable ref', async () => {
  await fc.assert(fc.asyncProperty(
    fc.record({ ref: fc.string({ minLength: 1 }), email: fc.emailAddress() }),
    async ({ ref, email }) => {
      const client = makeClientWith({ [ref]: { Email: email, FirstName: 'A', LastName: 'B' } });
      const contact = await client.lookupContact(ref);
      expect(contact.email).toBe(email);
    },
  ));
});

// Property 3: Missing contact halts processing
test('throws and surfaces the ref when contact is missing or has no email', async () => {
  await fc.assert(fc.asyncProperty(
    fc.record({ ref: fc.string({ minLength: 1 }), hasEmail: fc.boolean(), exists: fc.boolean() }),
    async ({ ref, hasEmail, exists }) => {
      fc.pre(!exists || !hasEmail);
      const client = makeClientWith(
        exists ? { [ref]: { Email: undefined, FirstName: 'A', LastName: 'B' } } : {},
      );
      await expect(client.lookupContact(ref)).rejects.toThrow(ref);
    },
  ));
});
```
