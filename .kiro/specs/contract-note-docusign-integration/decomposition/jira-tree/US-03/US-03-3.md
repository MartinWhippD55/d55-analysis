- **What:** Signed document download (combined) by envelope ID, using the retry utility
- **Why:** When signing completes, the Webhook Lambda (US-06) needs the signed PDF to store and forward. This retrieves the final combined document. Depends on JWT auth (US-03-1) and the US-01 retry utility.
- **Done when:**
  - The combined signed document is downloaded for a given `envelopeId` via `GET /v2.1/accounts/{accountId}/envelopes/{envelopeId}/documents/combined`, returning the PDF as a `Buffer`.
  - The download is wrapped in the shared `withRetry` utility (3 attempts, exponential backoff) so transient failures are retried.
  - On final failure the error is re-thrown for the caller to log.

### Suggested approach

```typescript
import * as docusign from 'docusign-esign';
import { withRetry } from 'shared-lib/retry'; // from US-01

async function downloadSigned(envelopeId: string, secret: DocuSignSecret): Promise<Buffer> {
  const apiClient = new docusign.ApiClient();
  apiClient.setBasePath(`${secret.authServer}/restapi`);
  apiClient.addDefaultHeader('Authorization', `Bearer ${await authenticate(secret)}`);
  const envelopesApi = new docusign.EnvelopesApi(apiClient);

  return withRetry(async () => {
    // 'combined' merges all envelope documents into a single signed PDF
    const result = await envelopesApi.getDocument(secret.accountId, envelopeId, 'combined');
    return Buffer.isBuffer(result) ? result : Buffer.from(result, 'binary');
  });
}
```
