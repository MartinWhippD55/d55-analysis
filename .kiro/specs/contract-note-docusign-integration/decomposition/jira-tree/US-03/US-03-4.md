- **What:** HMAC webhook signature validation (X-DocuSign-Signature-1, HMAC-SHA256)
- **Why:** The Webhook Lambda (US-06) must confirm that incoming Connect callbacks genuinely originate from DocuSign before acting on them. This is the security gate on the webhook flow (invalid → HTTP 401).
- **Done when:**
  - `validateHmac(payload, signatureHeader, secret)` computes an HMAC-SHA256 over the raw request body using the shared `hmacSecret`.
  - The computed digest is compared against the `X-DocuSign-Signature-1` header value using a timing-safe comparison.
  - It returns `true` only when the signature matches and `false` otherwise (including malformed/missing headers).

### Suggested approach

```typescript
import * as crypto from 'crypto';

function validateHmac(rawBody: Buffer | string, signatureHeader: string, hmacSecret: string): boolean {
  // signatureHeader is the value of X-DocuSign-Signature-1 (base64)
  const computed = crypto
    .createHmac('sha256', hmacSecret)
    .update(rawBody) // must be the RAW body, before any JSON parsing
    .digest('base64');

  const expected = Buffer.from(computed);
  const actual = Buffer.from(signatureHeader ?? '', 'utf8');
  if (expected.length !== actual.length) {
    return false;
  }
  return crypto.timingSafeEqual(expected, actual);
}
```
