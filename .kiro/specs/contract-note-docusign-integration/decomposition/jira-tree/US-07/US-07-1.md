- **What:** Extend render/parse-input.ts buildContractSummary to extract customersalesforceref, offerReference and customerName; thread Contract_Metadata through the state payload from parseInput to write-output and on to the SendEnvelope task. Coordinate with Estimate 1 owner (Jabez)
- **Why:** Estimate 1's landed pipeline extracts only `contractId`, so the customer reference never reaches the signing flow. Surfacing `Contract_Metadata` on the state payload is what lets US-05 know who to send each contract note to; US-08 then wires it into the `SendEnvelope` task. This is a change to landed Estimate 1 code — keep it additive and coordinate/review with the Estimate 1 owner (Jabez).
- **Done when:**
  - `buildContractSummary` in `api/src/render/parse-input.ts` extracts `customersalesforceref`, `offerReference` and `customerName` from the parsed `ContractData` (alongside the existing `contractId`).
  - A `contractMetadata` object of shape `{ salesforceRef, offerReference, customerName, contractNoteS3Key }` is threaded through the state payload from `parseInput` to `write-output.ts` and on to the `SendEnvelope` task.
  - When `customersalesforceref` is absent, the PDF is still produced but `contractMetadata` marks the reference absent so US-05 halts.
  - The change is reviewed against the landed render pipeline with its owner (Jabez); render behaviour is unchanged when the reference is absent.

### Suggested approach

```typescript
// api/src/render/parse-input.ts — additive extension of buildContractSummary.
// The ContractMetadata shape is the shared type owned by US-01.
import type { ContractMetadata } from "../types";

function buildContractSummary(contract: ContractData) {
  // existing:
  const contractId = contract.contractId;

  // new — surface the customer reference + related metadata:
  const contractMetadata: ContractMetadata = {
    salesforceRef: contract.customersalesforceref ?? null, // null => reference-absent, US-05 halts
    offerReference: contract.offerReference,
    customerName: contract.customerName,
    contractNoteS3Key: "", // filled once write-output.ts persists the PDF
  };

  return { contractId, contractMetadata };
}

// Thread contractMetadata through the Step Functions payload via the state
// machine's itemSelector / result-path so it survives from parseInput ->
// write-output.ts (which sets contractNoteS3Key) -> the SendEnvelope task.
// Keep additive: when salesforceRef is null the PDF is still produced and
// SendEnvelope's consumer (US-05) sees the reference-absent marker and halts.
```
