- **What:** Wire DocuSignPipeline into ContractNoteStack; append the SendEnvelope LambdaInvoke task after WriteOutput with its OWN DocuSign-specific catch (not render handleFailure) and its own retry/timeout; connect the API Gateway webhook route to the Webhook Lambda; set env vars (table, buckets, webhook URL, secret ARNs); finalise least-privilege IAM
- **Why:** This is the assembly step that turns the separately-built parts into a running,
  deployable pipeline: it appends the `SendEnvelope` task to the render state machine so
  signing follows a successful render, binds the webhook route to the Webhook Lambda, and
  finalises env vars and IAM. It unblocks the integration tests (US-08-2) and end-to-end
  deployment.
- **Done when:**
  - The `SendEnvelope` `LambdaInvoke` task is appended after `WriteOutput` in
    `cdk/lib/contract-notes/render-pipeline.ts`, invoking the US-05 send Lambda with the
    render output and Contract_Metadata, and given its OWN `addCatch` to a DocuSign failure
    handler (not the render `handleFailure`) plus its own retry/timeout.
  - The API Gateway `POST /docusign-webhook` route is connected to the Webhook Lambda.
  - Lambda env vars (table name, signed + reused error bucket names, webhook URL, secret
    ARNs) follow the `NodejsFunction` pattern used by `RenderPipeline`, and the
    `DocuSignPipeline` construct is wired into `ContractNoteStack`.
  - IAM grants are least-privilege for the DynamoDB table, the signed-documents and reused
    error buckets, and the required Secrets Manager secrets.

### Suggested approach

```typescript
// cdk/lib/contract-notes/render-pipeline.ts
// Append SendEnvelope after WriteOutput with its OWN catch + retry/timeout.
const sendEnvelope = new LambdaInvoke(this, 'SendEnvelope', {
  lambdaFunction: props.docusign.sendEnvelopeFn, // US-05
  payload: TaskInput.fromObject({
    output: JsonPath.stringAt('$.output'),
    contractMetadata: JsonPath.objectAt('$.Contract_Metadata'), // US-07
  }),
  resultPath: '$.sendEnvelope',
});

sendEnvelope
  .addRetry({ maxAttempts: 3, interval: Duration.seconds(2), backoffRate: 2 })
  // Own DocuSign-specific catch — NOT the render handleFailure, so a send
  // failure keeps the render successful and retains the produced PDF.
  .addCatch(props.docusign.docusignFailureHandler, {
    errors: ['States.ALL'],
    resultPath: '$.docusignError',
  });
sendEnvelope.timeout = Duration.minutes(2);

writeOutput.next(sendEnvelope);

// In ContractNoteStack: wire the construct + connect the webhook route.
const docusign = new DocuSignPipeline(this, 'DocuSignPipeline', {
  table, signedBucket, errorBucket, secrets,
});
webhookResource.addMethod('POST', new LambdaIntegration(docusign.webhookFn)); // POST /docusign-webhook

// env vars per NodejsFunction pattern used by RenderPipeline
docusign.sendEnvelopeFn.addEnvironment('TABLE_NAME', table.tableName);
docusign.sendEnvelopeFn.addEnvironment('WEBHOOK_URL', webhookUrl);
// least-privilege grants
table.grantReadWriteData(docusign.sendEnvelopeFn);
signedBucket.grantPut(docusign.webhookFn);
secrets.forEach(s => s.grantRead(docusign.sendEnvelopeFn));
```
