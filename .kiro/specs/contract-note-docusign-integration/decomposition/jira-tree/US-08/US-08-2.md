- **What:** Integration tests for the full pipeline flow (SendEnvelope -> DynamoDB record; valid webhook -> signed PDF in S3; invalid HMAC -> 401; declined -> notification in error bucket)
- **Why:** Validates the assembled pipeline end-to-end — that the `SendEnvelope` task,
  webhook route, HMAC verification and declined handling all work together once wired by
  US-08-1. It exercises the component stories' behaviour through the real deployment rather
  than in isolation.
- **Done when:**
  - A test drives the `SendEnvelope` task and verifies the envelope metadata record is
    written to DynamoDB.
  - A test posts a valid webhook and verifies the signed PDF lands in the signed-documents
    S3 bucket.
  - A test posts a webhook with an invalid HMAC signature and verifies a 401 response.
  - A test posts a declined webhook and verifies a notification record is written to the
    error bucket.

### Suggested approach

```typescript
describe('DocuSign pipeline integration', () => {
  it('SendEnvelope task writes envelope metadata to DynamoDB', async () => {
    await startRenderExecution(fixtureInput);
    const record = await getEnvelopeRecord(table, contractNoteKey);
    expect(record.envelopeId).toBeDefined();
  });

  it('valid webhook produces a signed PDF in S3', async () => {
    const res = await postWebhook(signedCompletedPayload, validHmac);
    expect(res.statusCode).toBe(200);
    expect(await objectExists(signedBucket, signedPdfKey)).toBe(true);
  });

  it('invalid HMAC is rejected with 401', async () => {
    const res = await postWebhook(signedCompletedPayload, 'bad-signature');
    expect(res.statusCode).toBe(401);
  });

  it('declined webhook writes a notification to the error bucket', async () => {
    const res = await postWebhook(declinedPayload, validHmac);
    expect(res.statusCode).toBe(200);
    expect(await objectExists(errorBucket, declinedNotificationKey)).toBe(true);
  });
});
```
