- **What:** Shared TypeScript interfaces and DynamoDB record types
- **Why:** One shared definition of every record and the specification tree, consumed by the API lambdas (US-02/03/04/05), the render pipeline (US-06) and the frontend (US-08). It removes divergent local copies and is the type contract US-01-3's validator operates on.
- **Done when:**
  - The `shared-lib:types` module defines the `SpecificationNode` union (`AndOrNode`, `NotNode`, `ComparisonNode`, `InNode`) covering AND/OR/NOT and EQUALS/LESS_THAN/MORE_THAN/IN.
  - AND/OR nodes use `leftOperand`/`rightOperand`, NOT uses a single `operand`, comparison leaves (`EQUALS`/`LESS_THAN`/`MORE_THAN`) use `field` + `value`, and `IN` uses `field` + `values`.
  - The `Template`, `Section` (with optional `pinnedVersionId`), `SectionVariant`, `SharedSection` and `SectionReference` interfaces are defined.
  - The DynamoDB record types are defined and the module lives in a shared `types/` location importable by the API lambdas, render pipeline and frontend.
  - The types compile and are consumed by at least one downstream module without redefinition.

### Suggested approach

```typescript
// shared-lib/types — single source of truth for records and the specification tree.
type LogicalOperator = 'AND' | 'OR' | 'NOT';
type ComparisonOperator = 'EQUALS' | 'LESS_THAN' | 'MORE_THAN' | 'IN';

export interface AndOrNode {
  type: 'AND' | 'OR';
  leftOperand: SpecificationNode;
  rightOperand: SpecificationNode;
}
export interface NotNode {
  type: 'NOT';
  operand: SpecificationNode;
}
export interface ComparisonNode {
  type: 'EQUALS' | 'LESS_THAN' | 'MORE_THAN';
  field: string;
  value: string | number;
}
export interface InNode {
  type: 'IN';
  field: string;
  values: (string | number)[];
}
export type SpecificationNode = AndOrNode | NotNode | ComparisonNode | InNode;

export interface Template {
  templateId: string;
  name: string;
  description: string;
  priority: number;
  sectionCount: number;
  createdAt: string;
  updatedAt: string;
  createdBy: string;
}

export interface Section {
  sectionId: string;
  name: string;
  sortOrder: number;
  isShared: boolean;
  sharedSectionId?: string;
  schemaS3Key: string;
  pinnedVersionId?: string; // version this reference resolves to at render time
}

export interface SectionVariant {
  variantId: string;
  name: string;
  variantOrder: number;   // evaluation order; first match wins
  isDefault: boolean;     // fallback when no rule matches
  schemaS3Key: string;
  specification?: SpecificationNode; // Variant_Rule; absent for the default variant
}

// Plus SharedSection, SectionReference and the DynamoDB record types
// (PK/SK-keyed shapes for Template, Section, Variant, Version, Rule, ChangeLog).
```
