- **What:** reorder-templates handler
- **Why:** Backs `PUT /contract-note-templates/reorder`. It lets a Business_User control rule-evaluation priority; the frontend drag-and-drop / up-down reorder (US-08) calls it, and the render pipeline's first-match-wins selection (US-06) depends on the ordering it writes.
- **Done when:**
  - The handler accepts an ordered array of template ids and batch-updates their `priority` values to contiguous integers starting at 1, matching the requested order.
  - The resulting priorities are contiguous from 1 and the relative order matches the request.
  - The updated ordering is persisted so it survives across sessions (re-querying the `PriorityIndex` returns the new order).

### Suggested approach

```typescript
// PUT /contract-note-templates/reorder
// Request body: { "templateIds": ["id-a", "id-b", "id-c"] }  // desired order
export const handler = async (event) => {
  const { templateIds } = JSON.parse(event.body ?? "{}");
  const now = new Date().toISOString();

  // Assign contiguous priorities 1..N in requested order
  const writes = templateIds.map((id, index) =>
    new UpdateCommand({
      TableName: process.env.TEMPLATES_TABLE,
      Key: { PK: `TEMPLATE#${id}`, SK: "METADATA" },
      UpdateExpression: "SET priority = :p, updatedAt = :u",
      ExpressionAttributeValues: { ":p": index + 1, ":u": now },
    }),
  );
  await Promise.all(writes.map((w) => ddb.send(w))); // or TransactWrite for atomicity

  return { statusCode: 200, body: JSON.stringify({ reordered: templateIds.length }) };
};
```
