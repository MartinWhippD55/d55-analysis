- **What:** Property tests for template API logic
- **Why:** Locks in the correctness properties carried from the parent spec across the four handlers (US-02-1..4). It guards the priority-management invariants (create/delete/reorder) that the render pipeline (US-06) relies on. Optional for a faster MVP.
- **Done when:**
  - fast-check property tests cover Property 1 (priority-ordered listing), 2 (create round-trip), 3 (new templates get lowest priority N+1), 4 (duplicate name rejection), 5 (required-field validation), 6 (update round-trip), 8 (delete keeps contiguous priority 1..N-1), 9 (shared sections survive deletion) and 10 (reorder produces contiguous ordering matching the request).
  - Unit tests cover priority-management edge cases: empty list, single template, and delete-from-middle re-compaction.
  - The tests run in CI and pass.

### Suggested approach

```typescript
import * as fc from "fast-check";

// Property 3: new template gets priority N+1
it("assigns the new template priority = count + 1", () =>
  fc.assert(fc.property(
    fc.array(templateArb, { minLength: 0, maxLength: 20 }),
    validCreateArb,
    (existing, req) => {
      const created = createTemplate(existing, req);
      expect(created.priority).toBe(existing.length + 1);
    },
  )));

// Property 8: delete leaves contiguous priorities 1..N-1
it("re-compacts priorities after delete", () =>
  fc.assert(fc.property(
    fc.array(templateArb, { minLength: 1, maxLength: 20 }),
    fc.nat(),
    (templates, i) => {
      const idx = i % templates.length;
      const remaining = deleteTemplate(templates, templates[idx].templateId);
      const priorities = remaining.map((t) => t.priority).sort((a, b) => a - b);
      expect(priorities).toEqual(remaining.map((_, n) => n + 1));
    },
  )));
```
