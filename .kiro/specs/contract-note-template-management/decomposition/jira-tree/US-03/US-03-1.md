- **What:** list/add/remove/reorder-section handlers (incl. T&C positioning)
- **Why:** These handlers back the `sections-crud` endpoint — the composition layer for a template's section list. They are what the Template Edit screen (US-08) drives to build document structure, and they write the `SECTION#{sortOrder}#{sectionId}` records US-02, US-04 and the render pipeline rely on.
- **Done when:**
  - `list-sections` returns a template's sections ordered by `sortOrder` ascending.
  - `add-section` appends with `sortOrder = current max + 1`; adding a shared section sets `isShared`, `sharedSectionId` and reuses the shared `schemaS3Key` (no duplication) and creates a `SHARED_SECTION#{id}` / `REF#{templateId}` reference record.
  - `remove-section` deletes the section and re-compacts the remaining sections to contiguous `sortOrder`, removing the shared-section reference if present.
  - `reorder-sections` persists the new order and keeps all T&C sections positioned after every non-T&C section.
  - Each mutating handler writes a template change log entry (see US-03-5).
  - Section/template not found returns 404.

### Suggested approach

`add-section` computes the next sort order and, for shared adds, creates a reference instead of copying the schema. Sketch of the handler:

```typescript
// POST /contract-note-templates/{id}/sections
export async function addSection(templateId: string, body: AddSectionRequest, user: string) {
  const existing = await listSectionRecords(templateId); // ordered by sortOrder
  const sortOrder = existing.length === 0 ? 0 : Math.max(...existing.map(s => s.sortOrder)) + 1;
  const sectionId = randomUUID();

  const section: Section = body.sharedSectionId
    ? {
        // shared add: reference, do not duplicate the definition
        sectionId, name: body.name, sortOrder,
        isShared: true,
        sharedSectionId: body.sharedSectionId,
        schemaS3Key: (await getSharedSection(body.sharedSectionId)).schemaS3Key,
      }
    : {
        sectionId, name: body.name, sortOrder,
        isShared: false,
        schemaS3Key: `${sectionId}/schema.json`,
      };

  await put({
    PK: `TEMPLATE#${templateId}`,
    SK: `SECTION#${sortOrder}#${sectionId}`,
    ...section,
  });
  if (body.sharedSectionId) {
    await put({ PK: `SHARED_SECTION#${body.sharedSectionId}`, SK: `REF#${templateId}` });
  }
  await recordChangeLog(templateId, 'section-added', `Added section "${body.name}"`, user);
  return section;
}
```

`reorder-sections` should sort the requested order, then force T&C sections to the tail before writing the recomputed `sortOrder` values. `remove-section` deletes the `SECTION#` record, its `REF#{templateId}` if shared, then rewrites remaining sections with contiguous `sortOrder` (0..N-1).
