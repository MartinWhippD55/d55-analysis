- **What:** get/save-section-schema handlers (writes a new version)
- **Why:** These back the `section-schema` endpoint that the embedded pdf-me Designer (Section Editor, US-08) reads from and saves to. Every save appends a Section Version record, which is the source of the version history (US-03-3) and the base US-04 publishing builds on.
- **Done when:**
  - `get-section-schema` reads the schema JSON from S3 at the section's `schemaS3Key` and returns it.
  - `save-section-schema` validates the schema JSON, writes it to S3, and appends a new `SECTION_VERSION#{sectionId}#{variantId}` record (variantId `default` when the section has no variants) with `createdAt` + `createdBy` — it does not overwrite the previous version.
  - After a save the section's version count increases by exactly 1; the prior version's schema JSON remains loadable.
  - Invalid schema JSON returns a 400; S3 read/write failure returns a 500.

### Suggested approach

`save-section-schema` validates, writes the blob, then records an immutable version:

```typescript
// PUT /contract-note-sections/{id}/schema
export async function saveSectionSchema(sectionId: string, schemaJson: unknown, user: string) {
  if (!isValidSchemaJson(schemaJson)) {
    return { statusCode: 400, body: { error: 'Invalid schema JSON format' } };
  }
  const timestamp = new Date().toISOString();
  const versionId = randomUUID();
  const variantId = 'default'; // sections without variants use the default variant
  const versionKey = `${sectionId}/versions/${versionId}.json`;

  // write current + immutable per-version blob
  await s3Put(`${sectionId}/schema.json`, schemaJson);
  await s3Put(versionKey, schemaJson);

  // append a version record; does NOT overwrite prior versions
  await put({
    PK: `SECTION_VERSION#${sectionId}#${variantId}`,
    SK: `VERSION#${timestamp}`,
    versionId, sectionId, variantId,
    schemaS3Key: versionKey,
    createdAt: timestamp,
    createdBy: user,
  });
  return { statusCode: 200, body: { versionId, createdAt: timestamp } };
}
```

`get-section-schema` reads the object at the section's `schemaS3Key` and returns it as the response body. Schema JSON is the pdf-me template definition (a `schemas` array, one entry per page); `isValidSchemaJson` should assert that shape.
