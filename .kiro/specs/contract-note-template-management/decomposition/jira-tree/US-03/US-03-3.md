- **What:** section version history handlers (list/get/revert)
- **Why:** These back the `section-versions` endpoint that lets a Business_User view and undo section edits from the Version History screen. This is also the component US-04 (publishing & variants) declares as a dependency — it exports `api-endpoint:section-versions`. Depends on US-03-2, which writes the version records these handlers read.
- **Done when:**
  - `list-section-versions` returns the section's version records ordered by timestamp descending (versionId, timestamp/createdAt, createdBy).
  - `get-section-version` returns a specific historical version's schema JSON (read from that version's `schemaS3Key`).
  - `revert-section-version` is non-destructive: it creates a new version (N+1) whose content is copied from the chosen historical version, leaving all intermediate versions accessible.
  - Section or version not found returns 404.

### Suggested approach

Query the version partition newest-first and implement revert as "read historical, write new":

```typescript
// GET /contract-note-sections/{id}/versions
export async function listSectionVersions(sectionId: string, variantId = 'default') {
  const items = await query({
    PK: `SECTION_VERSION#${sectionId}#${variantId}`,
    scanIndexForward: false, // VERSION#{timestamp} descending → newest first
  });
  return items.map(v => ({ versionId: v.versionId, createdAt: v.createdAt, createdBy: v.createdBy }));
}

// POST /contract-note-sections/{id}/versions/{versionId}/revert
export async function revertSectionVersion(sectionId: string, versionId: string, user: string) {
  const historical = await getVersionRecord(sectionId, versionId); // 404 if missing
  const schemaJson = await s3Get(historical.schemaS3Key);
  // non-destructive: re-save the historical content as a brand new version N+1
  return saveSectionSchema(sectionId, schemaJson, user);
}
```

`get-section-version` looks up the version record and returns the object at its `schemaS3Key`.
