- **What:** Property tests for section API logic
- **Why:** Locks the invariants the section handlers must uphold (ordering, append/remove behaviour, shared references, T&C positioning, schema round-trip, versioning, delete protection, change log) so US-03-1 through US-03-5 stay correct as they evolve. Optional for a faster MVP, but it is the safety net US-04 and the frontend build on.
- **Done when:**
  - fast-check property tests cover Properties 7, 11, 12, 13, 14, 15, 16, 17, 18, 19, 28, 29, 30 from the design.
  - Tests run against DynamoDB Local + localstack S3 (matching the design's integration strategy) and pass.

### Suggested approach

Use fast-check to generate arbitrary section sets and assert the invariants. Example for two of the properties:

```typescript
import fc from 'fast-check';

// Property 11: adding a section appends to the end (N -> N+1, highest sortOrder)
test('add-section appends with highest sortOrder', async () => {
  await fc.assert(fc.asyncProperty(
    fc.array(fc.record({ name: fc.string() }), { minLength: 0, maxLength: 10 }),
    async (initial) => {
      const templateId = await seedTemplateWithSections(initial);
      const before = await listSections(templateId);
      const added = await addSection(templateId, { name: 'new' }, 'tester');
      const after = await listSections(templateId);
      expect(after.length).toBe(before.length + 1);
      expect(added.sortOrder).toBe(Math.max(...after.map(s => s.sortOrder)));
    },
  ));
});

// Property 14: all T&C sections sort after every non-T&C section
test('T&C sections positioned at end', async () => {
  await fc.assert(fc.asyncProperty(
    fc.array(fc.boolean(), { minLength: 1, maxLength: 10 }), // isTermsAndConditions per section
    async (flags) => {
      const templateId = await seedMixedSections(flags);
      await reorderSections(templateId, /* arbitrary order */);
      const sections = await listSections(templateId);
      const maxNonTc = Math.max(...sections.filter(s => !s.isTermsAndConditions).map(s => s.sortOrder));
      const minTc = Math.min(...sections.filter(s => s.isTermsAndConditions).map(s => s.sortOrder));
      if (Number.isFinite(maxNonTc) && Number.isFinite(minTc)) expect(minTc).toBeGreaterThan(maxNonTc);
    },
  ));
});
```

Remaining properties follow the same shape: 7 (list ordered by sortOrder ascending), 12 (removal leaves contiguous order), 13 (shared add references, no copy), 15 (schema save→load round-trip), 16 (shared section visible in listing), 17 (shared edit propagates to referencing templates' schema load), 18 (references == templates including it), 19 (delete of referenced shared section blocked, returns referencing templates), 28 (save increments version count by 1, prior preserved), 29 (revert is non-destructive), 30 (every modification writes a change log entry with timestamp + user).
