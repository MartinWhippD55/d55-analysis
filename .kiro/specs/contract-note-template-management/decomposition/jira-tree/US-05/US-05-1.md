- **What:** get-rule handler
- **Why:** Provides the read half of the Rules API. It is the first handler in the story (save-rule depends on it in the task graph) and supplies the specification tree that the US-09 RulesConfigComponent loads into the editor and that the save/get round-trip (Property 20) is exercised through.
- **Done when:**
  - `GET /contract-note-templates/{id}/rule` fetches the `TEMPLATE#{id}` / `RULE` record and returns its `specification` JSON tree.
  - A request for a template with no rule record returns 404 (not found).
  - Unit test covers the 404 handling.

### Suggested approach

```typescript
// GET /contract-note-templates/{id}/rule
export const handler = async (event: APIGatewayProxyEvent): Promise<APIGatewayProxyResult> => {
  const templateId = event.pathParameters!.id!;

  const { Item } = await ddb.get({
    TableName: TABLE_NAME,
    Key: { PK: `TEMPLATE#${templateId}`, SK: 'RULE' },
  });

  if (!Item) {
    return { statusCode: 404, body: JSON.stringify({ message: 'Rule not found' }) };
  }

  // specification is the JSON tree: AND/OR -> { type, leftOperand, rightOperand },
  // NOT -> { type, operand }, EQUALS/LESS_THAN/MORE_THAN -> { type, field, value },
  // IN -> { type, field, values }
  return { statusCode: 200, body: JSON.stringify(Item.specification) };
};
```
