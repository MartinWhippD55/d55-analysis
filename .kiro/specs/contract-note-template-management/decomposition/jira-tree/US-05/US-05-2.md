- **What:** save-rule handler (validate specification)
- **Why:** Provides the write half of the Rules API and is the specification's well-formedness gate. It persists the rule that US-06's render pipeline later evaluates (first-match-wins across templates) and that the US-09 RulesConfigComponent saves. Depends on get-rule in the task graph and reuses the shared `spec-validation` utility from US-01.
- **Done when:**
  - `PUT /contract-note-templates/{id}/rule` validates the incoming specification tree with the shared `spec-validation` utility before any write.
  - A malformed tree (AND/OR missing operands, comparison nodes missing field or value) returns 400 with the incomplete node paths and does not persist.
  - A valid tree is persisted to the `TEMPLATE#{id}` / `RULE` record with `specification`, `updatedAt` (ISO 8601), and `updatedBy` (Cognito username).
  - Property tests cover the save/get round-trip (Property 20) and malformed-tree rejection (Property 21); a unit test covers validation error mapping.

### Suggested approach

```typescript
// PUT /contract-note-templates/{id}/rule
import { validateSpecification } from 'shared-lib/spec-validation'; // from US-01

export const handler = async (event: APIGatewayProxyEvent): Promise<APIGatewayProxyResult> => {
  const templateId = event.pathParameters!.id!;
  const specification = JSON.parse(event.body ?? '{}');

  const errors = validateSpecification(specification); // node-path errors for incomplete nodes
  if (errors.length > 0) {
    // Do NOT persist on validation failure
    return { statusCode: 400, body: JSON.stringify({ errors }) };
  }

  await ddb.put({
    TableName: TABLE_NAME,
    Item: {
      PK: `TEMPLATE#${templateId}`,
      SK: 'RULE',
      specification,
      updatedAt: new Date().toISOString(),
      updatedBy: getUsername(event), // Cognito username from the authorizer claims
    },
  });

  return { statusCode: 200, body: JSON.stringify(specification) };
};
```
