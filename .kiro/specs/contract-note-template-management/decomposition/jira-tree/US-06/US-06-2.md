- **What:** Template selection (first-match-wins)
- **Why:** This is the entry decision of the pipeline — it picks the template layout for the incoming contract data. It runs after `parse-input` and feeds the section render loop, so the `SelectTemplate` state cannot exist without it. Consumes the template selection rule persisted by US-05.
- **Done when:**
  - `lambda:select-template` fetches templates in priority order via `gsi:PriorityIndex` (US-01).
  - Each template's specification is evaluated with `shared-lib:spec-evaluator` (US-06-1) and the first one that evaluates true is returned, stopping evaluation (first-match-wins).
  - If no template specification matches, it logs an error with a contract summary and halts (failure record `stage: template-selection`), producing no output.
  - Property 22 holds (validated by US-06-8).

### Suggested approach

```typescript
import { evaluateSpec } from "shared-lib/spec-evaluator";

export async function selectTemplate(data: ContractData): Promise<TemplateRecord> {
  // Query the GSI to read templates in ascending priority (Template_List) order.
  const templates = await queryTemplatesByPriority(); // gsi:PriorityIndex, US-01

  for (const template of templates) {
    if (evaluateSpec(template.specification, data)) {
      return template; // first match wins — stop evaluating
    }
  }

  // No match: log to the error bucket and halt (no output).
  throw new NoMatchingTemplateError({ stage: "template-selection", data });
}
```
