- **What:** Section renderer (pdf-me) + pinned-version resolution
- **Why:** This produces the per-section PDF — the core rendering work of the pipeline. It runs inside the Map state (US-06-6) once per section and its output feeds the stitcher (US-06-5). It resolves the pinned-version data persisted by US-04.
- **Done when:**
  - `lambda:render-section` resolves the template reference's `pinnedVersionId` and uses that version, not necessarily the latest (Property 34).
  - It fetches the resolved version's schema JSON from `s3-bucket:schema-json` (US-01).
  - It renders via @pdfme/generator with the `text`, `multiVariableText` and `table` plugins and the NotoSans font, producing a non-empty valid PDF buffer (Property 24).
  - A render or schema-fetch failure is logged with section and template context and halts (failure record `stage: section-render`), producing no output.
  - Variant selection is handled by US-06-4 before the schema is fetched.

### Suggested approach

```typescript
import { generate } from "@pdfme/generator";
import { text, multiVariableText, table } from "@pdfme/schemas";

export async function renderSection(
  ref: SectionReference,
  data: ContractData,
): Promise<Uint8Array> {
  // Resolve the pinned version (US-04 data) — not the latest.
  const versionId = ref.pinnedVersionId;
  const schema = await getSchemaJson(ref.sectionId, versionId); // s3-bucket:schema-json, US-01

  const pdf = await generate({
    template: schema,
    inputs: [data],
    plugins: { text, multiVariableText, table },
    options: { font: notoSans },
  });

  if (!pdf?.length) throw new SectionRenderError({ stage: "section-render", ref });
  return pdf;
}
```
