- **What:** Section variant selection (first match, default fallback)
- **Why:** This chooses which layout variant of a section to render before US-06-3 fetches the schema and renders. It reuses the shared evaluator (US-06-1) and consumes the ordered variants and Variant_Rules persisted by US-04.
- **Done when:**
  - For a section with variants, each `Variant_Rule` is evaluated in `variantOrder` and the first match is selected (Property 35).
  - If no variant matches, the variant marked default is used as the fallback (Property 35).
  - A section with no variants uses the section's own schema, preserving single-variant behaviour (Property 36).
  - If a section has variants but none match and there is no default, an error identifying the section is logged and the pipeline halts with no output (Property 37).

### Suggested approach

```typescript
import { evaluateSpec } from "shared-lib/spec-evaluator";

export function selectVariant(
  section: Section,
  data: ContractData,
): SectionVariant | Section {
  // No variants: use the section's own schema (single implicit variant).
  if (!section.variants?.length) return section;

  // Ordered evaluation — first matching Variant_Rule wins.
  for (const variant of orderBy(section.variants, "variantOrder")) {
    if (variant.rule && evaluateSpec(variant.rule, data)) return variant;
  }

  const fallback = section.variants.find((v) => v.isDefault);
  if (fallback) return fallback;

  // No match and no default: log the section and halt.
  throw new NoVariantMatchError({ stage: "section-render", sectionId: section.id });
}
```
