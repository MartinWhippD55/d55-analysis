- **What:** Step Functions state handlers + Map state + failure state
- **Why:** This is the orchestration that wires the single-purpose Lambdas into observable, retryable states — the `state-machine:RenderStateMachine` export. It depends on template selection (US-06-2), variant selection (US-06-4) and the stitcher (US-06-5), and is the state machine US-10 later wires into deployment.
- **Done when:**
  - The state machine orchestrates discrete states `ParseInput` → `SelectTemplate` → `RenderSections` (Map) → `Stitch` → `WriteOutput`, with a `HandleFailure` catch on any state (parent 20.1).
  - The Map state processes each section as an independent, retryable unit with per-section retry (parent 20.2).
  - When a section-level state fails after its configured retries, the machine routes to `HandleFailure`, which writes an error record and no partial output (Property 38, parent 20.3).
  - The per-run outcome (success, or the failing state and reason) is recorded for observability (parent 20.4, 20.5).

### Suggested approach

```typescript
// CDK (aws-cdk-lib/aws-stepfunctions + tasks) — states wire the US-06 Lambdas.
const renderSections = new sfn.Map(this, "RenderSections", {
  itemsPath: "$.sections",
  resultPath: "$.sectionPdfs",
}).itemProcessor(
  new tasks.LambdaInvoke(this, "RenderSection", { lambdaFunction: renderSectionFn })
    .addRetry({ maxAttempts: 2, backoffRate: 2 }), // per-section retry
);

const definition = parseInput
  .next(selectTemplate)
  .next(renderSections)
  .next(stitch)
  .next(writeOutput);

const handleFailure = new tasks.LambdaInvoke(this, "HandleFailure", {
  lambdaFunction: handleFailureFn, // writes error record, no partial output
});

[parseInput, selectTemplate, renderSections, stitch, writeOutput].forEach((state) =>
  state.addCatch(handleFailure, { resultPath: "$.error" }),
);

new sfn.StateMachine(this, "RenderStateMachine", {
  definitionBody: sfn.DefinitionBody.fromChainable(definition),
});
```
