- **What:** XML-to-JSON parse + S3 trigger
- **Why:** This is the pipeline entry point — the `parse-input` Lambda plus the S3 input trigger that starts the state machine. Everything downstream (template selection, render, stitch) depends on the parsed contract data, so it is wired after the state machine (US-06-6) exists.
- **Done when:**
  - `lambda:parse-input` parses the dropped XML into a JSON contract-data object preserving all fields present in the XML (Property 26, parent 14.1, 14.2).
  - The pipeline starts on an `s3-bucket:input-xml` object-created event.
  - On success the output PDF is written to `s3-bucket:output-pdf` (parent 14.3).
  - On failure at any stage an error record is written to `s3-bucket:error-output` (US-01) and no partial output PDF is written (Property 27, parent 14.4).
  - Note: the final S3 event notification and IAM wiring for deployment are completed in US-10 (per the design's touch points); this sub-task delivers the parse handler and the trigger contract.

### Suggested approach

```typescript
import { XMLParser } from "fast-xml-parser";

const parser = new XMLParser({ ignoreAttributes: false });

// parse-input handler — invoked as the first state; the S3 event is on input-xml.
export async function handler(event: { bucket: string; key: string }) {
  const xml = await getObject(event.bucket, event.key); // s3-bucket:input-xml
  const data = parser.parse(xml); // preserve all fields present in the XML
  return { inputFile: event.key, data };
}
```

```jsonc
// S3 event contract that starts the RenderStateMachine (deployment wiring in US-10):
{
  "eventName": "ObjectCreated:Put",
  "s3": { "bucket": { "name": "input-xml" }, "object": { "key": "contract-123.xml" } }
}
```
