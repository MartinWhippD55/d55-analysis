- **What:** End-to-end pipeline integration tests
- **Why:** Once the stack is wired (US-10-1), these tests prove the feature works across real service boundaries rather than as isolated units. They exercise the parent's Property 27 / Property 38 (a failed run produces no output) end-to-end, giving confidence that the assembled pipeline succeeds and fails safely.
- **Done when:**
  - Dropping a valid XML into the input bucket results in a PDF appearing in the output bucket (parent 14.1, 14.3).
  - Dropping an invalid XML into the input bucket results in an error record in the error bucket and no output PDF (parent 14.4, Property 27).
  - Both tests run against the deployed/wired stack and assert on the actual bucket contents.

### Suggested approach

```typescript
// End-to-end tests against the deployed stack. Drop XML into the input bucket,
// wait for the RenderStateMachine to finish, then assert on bucket contents.
describe('render pipeline (end-to-end)', () => {
  it('valid XML -> PDF in output bucket', async () => {
    const key = `e2e/${randomUUID()}.xml`;
    await s3.putObject({ Bucket: inputBucket, Key: key, Body: validXml });

    const pdfKey = await waitForObject(outputBucket, expectedOutputKey(key));
    expect(pdfKey).toBeDefined();
    await expect(objectExists(errorBucket, expectedErrorKey(key))).resolves.toBe(false);
  });

  it('invalid XML -> error record, no output PDF (Property 27)', async () => {
    const key = `e2e/${randomUUID()}.xml`;
    await s3.putObject({ Bucket: inputBucket, Key: key, Body: malformedXml });

    const errorKey = await waitForObject(errorBucket, expectedErrorKey(key));
    expect(errorKey).toBeDefined();
    await expect(objectExists(outputBucket, expectedOutputKey(key))).resolves.toBe(false);
  });
});

// waitForObject polls the bucket with a timeout; the error record is the JSON
// failure record written by the HandleFailure Lambda from US-06.
```
