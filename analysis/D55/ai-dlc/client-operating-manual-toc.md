# Client Operating Manual — Table of Contents

*The kept asset. The client's own playbook for AI-native engineering — what good looks like for them, populated across the programme and owned by them after D55 exits.*

*This is the spine the modules write into. Each section names which part of the programme populates it, so it's clear how the manual fills up as the engagement progresses. Skills that generate the manual target this structure; `manual_section` in each module's frontmatter must match a section title here.*

---

## How the manual gets written

| Section | Populated by | When |
|---------|-------------|------|
| 0. Where We Are & Where We're Going | Phase 0 — Assessment | Start (free) |
| 1. Mandate & Measurement | Module 1 — Leadership & the Investment Case | Phase 1 |
| 2. How We Build | Module 2 — The AI-First Delivery Lifecycle | Phase 1 |
| 3. Shipping Safely | Module 3 — Shipping Safely | Phase 1 |
| 4. People & Operating Model | Module 4 — People & Change | Phase 1 |
| 5. Proof & Playbooks | Phase 2 — Embed (Prove-It) | Phase 2 |
| 6. Rollout & Self-Sufficiency | Phase 3 — Scale | Phase 3 |

The assessment starts it; the workshops fill the middle; the embed adds the evidence and real playbooks; rollout closes it out. By the end it's complete and it's theirs.

## 0. Where We Are & Where We're Going
*From the assessment. The starting picture.*
- Current-state radar (8 dimensions scored 1–5)
- Target-state radar (where they want to be in 12–18 months)
- The gaps, ranked, and which modules/phases each points to
- Four Fears snapshot (initial read on adoption resistance)

## 1. Mandate & Measurement
*From Module 1.*
- The executive mandate and named sponsor
- The mandate position (optional / encouraged / mandated)
- The investment case (sized to their org)
- The metrics scorecard we prove against
- Board/PE-ready ROI framing

## 2. How We Build
*From Module 2. The operational core.*
- AI tooling standard (shared configs, skills, MCP connections)
- The spec template (written for human + AI consumption)
- The adapted delivery process and ceremonies
- PR-review approach for AI-generated code
- Coordination-role definitions (the middle-layer shift)

## 3. Shipping Safely
*From Module 3. The guardrails.*
- AI usage policy
- Test strategy for AI-generated code (gates, coverage, review bar)
- Governance controls (approved tools, region, DLP, provenance, audit)
- EU AI Act classification (where applicable)

## 4. People & Operating Model
*From Module 4. The human system.*
- Four Fears diagnosis and per-pattern interventions
- Redefined roles (POs as spec owners, etc.)
- Upskilling / onboarding path
- The hybrid team operating model + handover plan

## 5. Proof & Playbooks
*From Phase 2. The evidence and the real how-to.*
- Metrics delta: baseline vs proven (the numbers that justify scaling)
- What shipped, and how it was built the AI-native way
- Concrete playbooks captured from real work (not theory)
- Capability-transfer record: what the client's people can now do

## 6. Rollout & Self-Sufficiency
*From Phase 3. The exit and beyond.*
- Rollout plan across other teams/squads
- The flywheel: how metrics → investment → adoption → metrics sustains itself
- What the client owns and runs without D55
- Where D55 remains available (light-touch, on demand)
